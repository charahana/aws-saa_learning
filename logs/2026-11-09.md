## ECSの起動方式
- ECSには主にEC2起動タイプとFargate起動タイプがある
| 比較項目 | EC2起動タイプ | Fargate起動タイプ |
| ------ | ------ | ------ |
| インフラ管理 | 自分で管理 | AWSが管理 |
| EC2の用意 | 必要 | 不要 |
| リソース管理 | インスタンス単位 | タスク単位 |
| 特徴 | 柔軟なインフラ管理 | サーバーレスで運用負荷が低い |

## EC2のインスタンスタイプ
- EC2には用途に応じたインスタンスタイプが存在する
| 分類 | 特徴 | 代表例 |
| ------ | ------ | ------ |
| 汎用 | CPUとメモリのバランスが良い |M、T |
| コンピューティング最適化 | CPU性能を重視 | C |
| メモリ最適化 | 大容量メモリを利用 | R、X、U |
| ストレージ最適化 | 高速/大容量ストレージ | I、D、H |
| 高速コンピューティング | GPUなどを利用 | P、G、Inf |
### 各インスタンスタイプの解説
- Mシリーズ：一般的なアプリケーション向け
- Tシリーズ：バースト可能な汎用インスタンス
- Cシリーズ：CPU負荷の高い処理向け
- Rシリーズ：メモリを多く必要とする処理向け
- Iシリーズ：高速なストレージI/Oが必要な処理向け
- Pシリーズ：GPUを利用する機械学習や高性能計算向け

## インスタンスストアとEBSの違い
| 比較項目 | インスタンスストア | EBS |
| ------ | ------ | ------ |
| ストレージ | EC2ホストに物理接続 | ネットワーク接続 |
| データ保持 | 一時的 | 永続的 |
| 主な用途 | キャッシュ、一時データ | OS、DB、永続データ |
| EC2停止時 | 原則データ消失 | データ保持 |
### まとめ
- インスタンスストアは一時的なデータ保存に適している
- EBSはEC2とは独立してデータを保持できる
- EC2終了後もデータを保持したい場合はEBSが適している
- インスタンスストアは高速な一時ストレージとして利用できる

## EC2の購入オプション
| 購入方式 | 特徴 | 適した用途 |
| ------ | ------ | ------ |
| オンデマンド | 必要なときに利用できる | 短期/不定期利用 |
| リザーブドインスタンス | 1年/3年の利用コミットメント | 長期/安定利用 |
| Savings Plans | 一定の利用料金をコミット | 継続的な利用 |
| スポットインスタンス | 余剰キャパシティを安価に利用 | 中断可能な処理 |
| Dedicated Hosts | 物理サーバーを専有 | ライセンス要件など |
| Dedicated Instances | 物理ハードウェアを他アカウントと共有しない | 物理的な分離要件 |
### まとめ
- オンデマンド：長期契約をせず柔軟に利用できる
- リザーブドインスタンス：長期利用を前提に料金を削減できる
- Savings Plans：一定の利用料金をコミットすることで割引を受けられる
- スポットインスタンス：低コストだが中断される可能性がある
- Dedicated Hosts：物理サーバーを専有できる
